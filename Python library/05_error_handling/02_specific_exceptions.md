# Specific Exceptions

> **Core idea:** Handle failure types differently.

## Learning objectives

- Explain why the technique exists and identify where it is useful.
- Predict and verify the companion program's behavior.
- Recognize the main pitfall and solve a variation independently.

## Concept and motivation

**Specific Exceptions** is part of the broader topic **Error Handling**. Handle failure types differently. Think of it as a tool for expressing a particular operation clearly rather than syntax to memorize. When reading an implementation, ask: *What information goes in? What operation happens? What result or side effect comes out?*

## Common mistakes and edge cases

**Pitfall:** Do not treat missing keys and invalid values alike.

Try an empty input, unexpected type, boundary value or error condition where appropriate. If the sample does not contain that case, implement it in your practice copy. Do not assume one successful example proves a general rule.
