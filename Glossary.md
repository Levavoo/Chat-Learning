# Glossary

A short A–Z reference for **researched and explained** terms. Add new terms to [[Terms]] first, and transfer them here only after verifying a clear English definition and classification. Every entry uses **Term — kind — simple definition**. Detailed explanations belong in separate linked notes, not in this file.

Categories include: command, technology, framework, library, architecture-style, architectural-pattern, protocol, service, tool, concept, language and platform.

**Workflow:** add a term here when you first encounter it. Once you create a detailed note, link its title using `[[wikilinks]]`. Keep definitions generic and exclude private workplace details.

## A

- **API — concept:** An interface through which one program can request data or actions from another.
- **AWS — platform:** Amazon's cloud platform for compute, storage, databases, networking and more.
- **AWS Bedrock — service:** Managed AWS access to foundation models and related generative-AI capabilities.

## B

- **Batching — concept:** Processing a group of items together instead of one at a time.
- **BM25 — algorithm/concept:** A keyword-based relevance ranking method often used in information retrieval.
- **Buildah — tool:** A tool for building container images.

## C

- **CDN — technology:** A distributed network that caches and delivers content closer to users.
- **CI/CD — practice/concept:** Automated checking, building, and delivery of software changes.
- **Chunking — technique/concept:** Splitting documents into smaller units for indexing or processing.
- **CloudWatch — service:** AWS monitoring service for metrics, logs and alarms.
- **Cognito — service:** AWS identity service for application user authentication.
- **Container — technology:** A packaged application and its runtime dependencies that run using operating-system isolation.

## D

- **DLQ (dead-letter queue) — concept:** A place to retain messages that could not be processed successfully.
- **Docker — technology/tool:** Tooling for building and running containerized applications.
- **DynamoDB — service:** AWS managed NoSQL database.

## E

- **ECR — service:** AWS Elastic Container Registry, used to store container images.
- **Embedding — concept:** A numeric representation that can capture useful patterns or semantic relationships.

## F

- **Framework — concept:** A reusable structure that provides conventions and components for building software.

## G

- **Git — tool:** Distributed version-control system for tracking file changes.
- **Guardrail — concept:** A control intended to restrict or check unsafe or unwanted system behavior.

## H

- **HTTP — protocol:** Request-response protocol used for communication on the web.
- **HyDE — technique/concept:** Hypothetical Document Embeddings, a retrieval technique that uses a generated hypothetical answer or document to help search.

## I

- **IAM — service/concept:** Identity and access management; in AWS, controls permissions for users and workloads.
- **IaC — practice/concept:** Infrastructure as Code, the practice of defining infrastructure with versioned configuration.

## L

- **Lambda (AWS) — service:** Runs code in response to events without managing the underlying servers.
- **Langfuse — tool/platform:** Observability and evaluation tooling for LLM applications.
- **Linting — concept:** Static checks for code style, common errors and selected correctness rules.

## M

- **Make — tool:** Runs named build or automation targets described in a Makefile.
- **Mermaid — tool/notation:** Text-based syntax for diagrams embedded in Markdown.
- **Microservices — architecture-style:** An approach where functionality is split across separately deployable services.

## N

- **Nix — tool/technology:** Reproducible package and environment management using declarative expressions.
- **npm — tool:** Package manager and script runner for the JavaScript ecosystem.

## O

- **OIDC — protocol:** OpenID Connect, an identity layer built on OAuth 2.0.
- **OpenTofu — tool:** Infrastructure-as-code tool for provisioning and managing infrastructure.

## P

- **PEP 8 — standard/concept:** Python's style guide for code formatting conventions.
- **pytest — framework:** Python testing framework.
- **PydanticAI — framework:** Python framework for building model-powered applications and agents.

## R

- **RAG — architectural pattern:** Retrieval-Augmented Generation, where retrieved content supplements an LLM prompt.
- **REST — architecture-style:** Architectural style using resource-oriented, stateless interactions.
- **Reranking — technique/concept:** Reordering retrieved results using an additional relevance model.
- **Ruff — tool:** Fast Python linter and formatter.

## S

- **S3 — service:** AWS object storage used for files and other data objects.
- **S3 bucket — concept:** A named container for objects stored in S3.
- **Serverless — architecture/execution model:** Running applications without directly managing the underlying server infrastructure.
- **SQS — service:** AWS managed message queue for decoupling application components.
- **SSM — service family:** AWS Systems Manager, for managing and operating infrastructure.

## T

- **Terraform — tool:** Infrastructure-as-code tool for managing provisioned resources.
- **TLS — protocol:** Cryptographic protocol for securing data in transit.
- **TypeScript — language:** JavaScript with a static type system.

## U

- **uv — tool:** Fast Python package and project manager.

## V

- **VPC — service/concept:** Virtual Private Cloud, an isolated logical network in AWS.

## Y

- **YAML — data format:** Human-readable serialization format commonly used for configuration.
